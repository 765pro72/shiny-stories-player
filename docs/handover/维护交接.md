# 闪耀色彩中文剧情馆：维护交接

项目目录：`F:\sc`。这是一个**非官方剧情播放器**，并非《偶像大师 闪耀色彩》原页游的完整离线版。用户希望它能在 Windows 上以文件夹或 ZIP 分享、无网络阅读已收录剧情、拥有官方风格主页与可更换的看板偶像，并能跟随公开资料更新。不要把未取得的资源或未完成的翻译描述为已完成。

## 先做什么

1. 在 `F:\sc` 查看 `exports/offline-verification.json` 和 `exports/offline-assets-needed.json`。资源镜像可能仍在运行；如未运行，执行 `node scripts/cache-all.cjs --assets`，它会跳过已下载文件，失败后可重试。
2. 下载完成后运行 `node scripts/verify-offline.cjs`。它对 130 篇源站 404 脚本仍会报不完整；这些编号在 `exports/offline-scripts-failures.json`，不可假定可播放。`npm run release` 的校验允许**仅这批已确认 404**的脚本缺失，但会拦住其余任何缺失资源。
3. 核查资源失败记录，必要时重试下载并检查是否是资源路径推导错误。随后执行 `npm run release`，得到 `dist/ShinyStories-win32-x64/ShinyStories.exe` 与 `dist/ShinyStories-win32-x64.zip`。用断网或 `SHINY_OFFLINE=1` 测试主页、卡片相册、剧情播放、音声与图片。不要在校验失败时交付为“完整离线版”。
4. 更新这份文档中的数字，整理正式版说明和已知缺失，再交付给用户。

## 代码结构

- `server.cjs`：只监听 127.0.0.1，提供 `public/`、`data/` 和 `/asset/`。资源优先从用户缓存读取，再从安装目录 `cache/` 读取，最后联网按需取得。设置 `SHINY_OFFLINE=1` 时禁止资源联网回退，用于验证。更新后的数据缺文件时回退到内置 `data/`。
- `desktop.cjs`、`preload.cjs`：Electron 入口；收藏、阅读记录、补译和主页设置保存在 Electron `userData`；应用内“检查数据更新”经 `updater.cjs` 实现。
- `updater.cjs`、`scripts/catalog.cjs`：从 ShinyGroup 翻译仓库及 ShinyColorsDB Album 的公开 GitHub 快照重建目录与译文；更新是**手动触发**的，未来游戏新增剧情是否出现取决于上游是否收录。更新时复制内置 `card-art.json`，所以新卡图仍需维护映射。
- `data/catalog.json`、`data/translations/`、`data/card-art.json`：目录、译文与卡图映射。卡图由卡片编号映射到 `images/content/{idols|support_idols}/card/{id}.jpg`。不要按相似卡名猜图。
- `data/unavailable.json`：当前 130 篇脚本源站 404 的快照；剧情馆将其标成“脚本暂缺”并禁止打开。若未来源站补齐，重新生成此清单。
- `public/index.html`、`home-idol.js`、`home-multi.js`、`home.css`：官方风格主页；最多 5 名看板偶像；多人尺寸和位置在 `home-multi.js` 的 `sizes` 与 `layout()` 中。某些官方 Spine 立绘的腿本来未画完整，因此当前让下方菜单遮挡立绘边缘。
- Spine 的 `wait1` 等待机动画含 `loop_start` 事件；`home-idol.js` 的 `installIdleLoop()` 在事件到达时把 TrackEntry 的循环范围收窄为事件之后的片段，供单人和多人模型共用。不要等 `complete` 回调才改 `trackTime`：那时开头姿势已经渲染了一帧，会看到一次抽动。
- `public/library.html`、`app.js`、`app.css`：分类检索、卡片相册、分页输入跳转、剧情列表与播放弹窗。
- `public/player/`：剧情渲染和音画播放。播放依赖 `/asset/` 和本地翻译 JSON。
- `scripts/cache-all.cjs`：可恢复的脚本/资源镜像。默认阶段下载脚本，`--assets` 阶段扫描脚本中的图片、Spine、语音、BGM、视频，再补卡图和主页资源。资源清单输出到 `exports/offline-assets-needed.json`。
- `scripts/cache-card-art.cjs`：卡图优先下载。已匹配卡图在本地，但未匹配组仍需研究。
- `scripts/verify-offline.cjs` 与 `scripts/release.cjs`：离线校验和正式打包门禁。最终 ZIP 用 Windows `tar.exe` 生成。
- `scripts/export-missing.cjs`：生成 `exports/未汉化文本-2026-10-15.zip`。其中 07 是没有翻译文件的剧情可取得的日文全台词；08 是脚本源站缺失清单。此日期包应随目录更新重新生成并更名。

## 当前已知缺口（2026-10-15，数字需重算）

- 目录 7,480 篇；7,350 个脚本已下载。130 篇特殊剧情的公开资源服务器返回 404。不要宣称这 130 篇离线可播放。
- 资源清单约 195,759 个（镜像运行时可能重算）；尚未全下完。下载可数小时；磁盘空间应保持充足。最终产物会很大。
- 镜像曾发现 `sounds/bgm/pause.m4a`、`resume.m4a` 是控制指令，不是真实音频；播放器与扫描器已修正。`images/content/game_event_communications/card/400103307.jpg` 在当前公开资源服务器返回 404，播放器会跳过这张剧中静态图以免整篇崩溃；不要把它算作已取得的画面。后续可寻找可靠来源补齐并移除特殊跳过逻辑。
- 卡片剧情 2,274 篇，2,239 篇已匹配卡图，35 篇缺少可靠卡图编号。已匹配的 693 个独立卡图文件已优先下载。列表里其他类型的剧情不应强行显示卡面。
- 翻译：5,611 篇有翻译文件，但不代表全部句子已汉化或润色。缺译包有 8,103 条部分汉化剧情缺译记录（含符号/注释），其中 659 条有文字内容；另有 1,507 篇完全无翻译文件的剧情可取得 16,314 条日文台词。29 条主页语音有原文但缺中文，117 条主页语音尚无原文。用户明确希望**千问完成所有翻译和润色**，不要由维护 AI 自行生成或冒称已由千问完成。目前千问大规模翻译与全量润色仍未完成。
- 用户要求高清素材保持官方五官与画风，不接受重绘改变细节。曾生成的 AI 放大样本未投入应用。原始画面素材包在 `exports/画面素材-2026-10-15.zip`，但只涵盖当时已缓存的 101 个视觉文件，不是全量资源包。
- 更新功能现在会在新目录启用前尝试缓存新增剧情脚本与引用资源到 Electron 用户数据目录；仍取决于公开上游是否收录且资源可访问。卡图映射也需后续维护，正式安装包需要重跑镜像与发布才能把新增资源内置进去。

## 发布前检查

1. `node --check` 检查修改过的 JS；运行 `node scripts/verify-offline.cjs` 并逐条看缺失，确认除 130 个明确 404 脚本外无缺失。
2. `npm run release` 的门禁通过后，检查 `release-manifest.json` 的数字与 ZIP 内目录。
3. 在干净 Windows 用户配置或临时用户数据下启动 EXE；断网测试主页单人/五人、切换服装及语音、分类/页码跳转、卡图、任意不同类别的剧情和全屏。至少抽查语音、Spine、BGM、视频、背景图路径。
4. 联网测试应用内“检查数据更新”，确认失败不会破坏旧目录，也确认新目录能回退读取 `card-art.json`。
5. 给用户的发布说明必须列出无法播放的 130 篇、未匹配卡图 35 篇，以及尚未完成的千问翻译/润色；别把这个产品称为原游戏的本地破解版。

## 维护时的关键原则

- 用户对“完整离线、后续可更新”的要求一直有效。脚本或资源缺失时继续修复；如果上游确实没有，给出明确清单。
- `data/catalog.json` 中所有 `special_communications/` 已归到“特殊剧情”，`mypage_communications/` 归到“主页剧情”；`scripts/catalog.cjs` 对公开相册新增项也按前缀分类。部分 W.I.N.G./LP 卡剧情还需在重建目录后重新验证，避免分类回退。
- 主页画面要沿用官方素材，不要用生成图替换偶像五官/画风。卡图只用能证实的卡片编号。
- 不要修改翻译来源归属；保留社区译者标识。千问润色结果应保留原文、原译、审校状态及可回滚记录。
