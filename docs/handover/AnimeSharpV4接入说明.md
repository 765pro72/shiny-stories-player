# UI 2026-11-13.9：独立超分开关与执行顺序

已接入 AnimeSharpV4，不再是上轮的单帧研究样本。CuNNy 的运行时、权重、旧叠加分支、构建/测试及比较脚本已删除；旧 Full 成品与用户缓存不动，当前仅发布 Lite。

## 使用

看板设置、剧情菜单、语音试听、相册查看器中的“画质增强”共有两项，各自有开关与档位：

- AnimeSharpV4：完整 RCAN 2×、快速 RCAN PixelUnshuffle 2×。
- Anime4K：S/M/L/UL 2×、UL 4×。

拖动左侧把手调整上下顺序，也可点上下箭头；**从上到下执行，关闭的项完全跳过**。全部关闭即原图。排序、档位与当前会话状态跨模块共享；新启动仍默认全部关闭，保留档位和排列。

只开 Anime4K 沿用实时画面处理；启用 AnimeSharpV4 后，对原始纹理按所选顺序处理并复用，避免每帧运行重型 RCAN。两项同时开启时，两者确实依次处理同一纹理：“RCAN→Anime4K”和“Anime4K→RCAN”是不同计算，不只是界面排序。动画骨骼、动作、台词、命中区域与逻辑尺寸不变。处理期间原图继续显示，可切回原图。

视频帧暂只支持单独 Anime4K；不把 RCAN 的低速逐帧结果伪装成流畅实时视频。超大组合可能超出显卡纹理/内存能力，失败保留原图并提示。低帧率提示与降档/恢复原图保留，不覆盖首选链。

## 下载与缓存

Lite 内置 Windows x64 的 ONNX Runtime / DirectML 运行组件，不打包未用平台和训练代码。完整与快速两份约30 MB的作者ONNX权重均已随包提供，经固定 SHA-256 校验；无须首次下载。完整与快速是两个不同权重。

权重、来源/许可说明及处理后的 PNG 集中在程序“下载资源/超分资源/AnimeSharpV4”；本地目录不可写时沿用应用用户目录的下载文件夹，可用已有“打开下载文件夹”。静态输入仅在本机处理，未向第三方上传图像。原始官方纹理不覆盖。

## 保真与技术处理

独立 Worker 使用 DirectML，失败时明确显示 CPU 处理，前台不等待同步推理。图集按物理部件分别处理，透明区域颜色向内源颜色延伸；alpha 独立重采样。平坦区域保留源颜色，减少神经网络造成的肤色差异和拼接线。分块有上下文及重叠融合。

处理后只替换内存中的纹理来源并设置相应像素密度，逻辑宽高、Spine 的 atlas / mesh / bone 坐标不改。关闭后恢复原资源引用；异步返回的旧任务不得重新启用已关闭的模型。卡面保存使用最终增强图，而不是低分辨率窗口截图。

## 验证与边界

test-animesharp 使用真实权重和独立隐藏窗口，验证两个顺序产生不同结果、拖动排序、关闭项跳过、原图恢复、真乃71个图集部件、几何与骨骼位置不变、透明度平均误差约0.31/255、闭眼动画。还保留 Anime4K 档位、取消、上下文丢失、低帧率提示回归。

这是有限样本验证，不能保证所有衣装都没有细微伪影；任何超分都不能恢复源素材已经丢失的全部细节。未改动受保护的离线超分目录与翻译。

发布经过 npm run release -- --refresh-ui，使用 7-Zip 更新 ZIP；另按已验证 ZIP 的完整成员列表生成 LZMA2 .7z，避免把用户新增下载和配置误装进分享包。最终以 exports 中的发布核验报告为准。

补充：文本纹理不参与超分；增强画布同步交互像素密度，实际点击坐标回归通过。仅修改关闭项的档位或顺序时不重复处理当前有效链。
