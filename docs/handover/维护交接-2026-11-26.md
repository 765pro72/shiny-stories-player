## 2. 核心技术问题根因与彻底修复记录

### 问题 A：Spine 立绘眼部/腮红硬框（Seam）
- **根因**：官方 Spine 原画中，`eye_mask`、`face_shadow`、`cheek` 等叠加层贴图的外包矩形（Bounding Box）直接切在不透明度 > 140 的半透明渐变区域上。直接 2x 超分后，硬裁切边界与底色皮肤产生明显的方块接缝。
- **解决方案**：在提取图集时检测半透明零件边界，当边缘存在非零 alpha 时，向内做 6px 线性衰减羽化（Feathering Ramp），无缝融入皮肤。该逻辑已整合入流水线。

### 问题 B：多线程并发导致的“刘海网格噪波/花屏”（Race Condition）
- **现象**：凛世等角色的前额刘海或衣物细节出现黑白网格斑驳噪点（如 `media_1795619150435_7eff286b.jpg`）。
- **根因**：超分模型为 `2xHFA2k_LUDVAE_SPAN`（SPAN 架构）。其内部核心模块 `Conv3XC` 在 `eval` 模式下每次 forward 都会动态执行 `update_params()` 将三层卷积与残差融合进 `eval_conv`。在 Python 多线程并发时，多线程同时向该共享模块写回权重，引发**严重内存竞态（Race Condition）**，导致卷积核参数错乱！
- **彻底修复方案**：
  在模型载入后、推理执行前，单线程执行一次权重固化预融合（Pre-fuse），将 `eval_conv` 固化并替换 forward 函数（禁止再调用 `update_params()`）。
  ```python
  from spandrel.architectures.SPAN.__arch.span import Conv3XC
  for m in model.modules():
      if isinstance(m, Conv3XC):
          m.update_params()
          def _fast_fwd(self, x):
              out = self.eval_conv(x)
              if self.has_relu:
                  out = torch.nn.functional.leaky_relu(out, negative_slope=0.05)
              return out
          m.forward = types.MethodType(_fast_fwd, m)
  ```
  本地已通过 DirectML 严格实测：**预融合后多线程/单线程均 100% 稳定，噪点数为 0**。
