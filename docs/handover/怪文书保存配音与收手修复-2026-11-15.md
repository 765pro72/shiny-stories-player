# 怪文书保存配音与收手修复（UI 2026-11-15.8）

## 保存后有声音但不张嘴

已复现：AI 草稿里的角色加入编辑器时会取得新编号，配音素材仍保存草稿角色编号。此前播放优先取配音内的旧编号，所以草稿预览正常，加入编辑器、保存并重新打开后的实际角色却无法收到嘴型。

`CustomStory.voiceActor` 现在先按当前台词的说话人和当前镜头模型解析角色；只有无法按姓名解析时，才接受确实存在于本镜的原绑定编号。主对白和镜头内定时配音共用此规则。制作人、旁白、空说话人始终不绑定偶像，没有“只有一人就让她张嘴”的兜底。旧作品无需重新付费生成配音。

## 抬手动作结束时手臂穿到身体后面

用户提供 `QQ_2026-11-15_13-58-32.mp4`，逐帧可见手仍抬起时前侧手臂部件已隐藏。此前仅将骨骼约 0.3 秒混合到下一动作，忽略原动画 `relay` 事件，直接使用待机的部件显隐；两者不同步。

现在读取前一身体动作中模型实际提供的 `relay` 事件，先播放对应的原生收手过渡（例如 `arm_down`），再接下一身体动作。骨骼和前后手臂部件使用同一条原生动画采样。快速切到下一个连续镜头时延续尚未完成的收手，不重新开始；身体、表情、视线和配音轨仍独立。未带过渡事件的模型沿用原有渐变，没有猜测动画名称或改写官方 JSON、贴图。

## 同类检查：眼神变化不能拖动身体

复现收手过程中眼神变化重启全身骨骼渐变，原生手臂在同一采样点有约52.17°偏差。现在按实际变化轨道的骨骼／约束范围独立渐变，每个骨骼保留自己的过渡时间；嘴型不参与姿态混合。交叉回归中收手局部骨骼与原生动画误差为0，左右视线仍有连续中间值。原视线测试误采了身体动画驱动的父节点 eyeball，已改为实际眼神轨驱动的 eyeball_L，断言没有放宽。

## AI 纠错

分镜脚本下的“AI 修复脚本”升级为“AI 纠错”，可独立于提纲和扩写使用。检查动作、情绪衔接、说话人／倾听者、时间轨和格式；可以填写重点问题。返回问题说明和完整脚本，先通过本地素材／动作／归档规则及对白保护，再替换预览草稿，不自动写入编辑器。支持撤销、停止、无 API 复制纠错提示词，以及粘贴外部 AI 结果。既有台词、日语、朗读语言／混读分段、配音和已知素材引用、角色数及镜头数受到本地保护；AI 擅改时拒绝应用并保留原稿。模型不能修复程序或未知模型几何，提示词不冒称具备此能力。
