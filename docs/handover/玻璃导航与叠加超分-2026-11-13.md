# 玻璃导航、模块目录与叠加超分

本轮按用户反馈继续改 UI，仅发布 Lite，UI 版本 2026-11-13.6。

## 导航失灵的真实原因与修复

真实的隐藏 Electron 窗口测试复现了：跨文档 View Transition 期间，导航被捕获成快照，点击位置的 DOM 命中结果是 html；pointerdown 取消动画，随后 pointerup 命中链接，两次目标不同，浏览器不会把第一次点击交给链接。单纯给快照加 pointer-events:none 或取消动画均不足以解决。

navigation.js 在转场期间保留鼠标下方可操作元素，并且只在浏览器把点击交给 html 等祖先时，将同一次、无拖动、无修饰键的点击转交一次给原控件。正常链接点击不重复执行，pointercancel 清除记录。链接、按钮及 summary 支持该处理。仍保留完整转场、选中胶囊和弹性反馈。

scripts/test-shell-interaction.cjs 使用实际 HTML/CSS、原生透明窗口控制覆盖层，在自己的隐藏窗口中发出真实 Chromium 鼠标输入：六次模块跳转，其中五次发生于快照转场中，全部成功。报告 exports/shell-interaction-verification.json。没有控制用户现有窗口。

## 玻璃与页面布局

- 大厅场景从 y=0 覆盖整个客户区，导航/品牌为独立通透玻璃控件，不再让白色页头占据画面。移除了将所有大厅 header 向下偏移的旧规则。
- 顶部空隙和 10px 上边缘负责拖动，链接和按钮明确 no-drag；右上角原生控制区有透明玻璃承托，继续保留 Windows 原生最小化、最大化、关闭按钮。
- desktop-window.watchWindowChrome 按窗口内容宽度同步原生按钮行高度；CSS 对应 header-height：普通 82px，1900px 起 clamp(82px,3.6vw,130px)。不能把整个 site-header 标为 drag。
- 大厅全屏请求改为整个文档，顶部导航也属于全屏内容；清屏仍隐藏导航并保留字幕。
- 衣装室：随当前衣装关联卡面变化的渐变标题区、偶像索引、日常/舞台/剧情快速分类、独立衣装预览台；仍使用 3210 张随包预览图。
- 相册：标题真实卡面保留固定/随机选择，组合索引有分组编号与柔和色块，搜索/稀有度/排序等工具只属于卡面区，卡片有稀有度徽标。
- 语音馆：独立声音分类索引、语音目录及右侧主角试听台，标题采用同角色官方卡面的渐变构图；电话仍使用现有官方素材电话界面。
- 各页采用剧情馆的视觉索引、层次和留白，但衣装、卡面、语音布局各自不同。沿用 distinctive-ai-design、UI UX Pro Max 与 Lens 参考中的适用原则，完整动效不按系统偏好减弱。材质仍是 CSS 玻璃适配，不冒称接入 Lens 的整个 WebGL 折射合成器。

实际浏览器自查 1024×768、1280×720、3840×2160；卡面默认适应窗口，SSR/SR 筛选、排序、衣装分类、扮演语音试听及模型载入可用。1024 窗口打开卡面时对话框 scrollHeight=clientHeight。截图位于 exports/大厅镶嵌玻璃导航-2026-11-13.png、衣装室预览台-2026-11-13.png、语音馆声音索引-2026-11-13.png。

## 可选 CuNNy → Anime4K

新增共用档位 cunny-anime4k：CuNNy NVL 8×32 先 2×，将实际输出帧送入 Anime4K CNN_UL 再 2×，总 4×。第二阶段不重复 Clamp/Restore，避免额外修复涂抹。没有改动原纹理、离线超分目录或模型权重。画质不保证优于单独模型，可能柔化或产生伪细节。

默认仍 off，单独 CuNNy/Anime4K 档位保留。持续低帧率：叠加→单独 CuNNy 8×32→4×32→4×16→3×12→原图，每次告知，首选档位不被覆盖。两阶段严格同一 postrender 内顺序执行，CuNNy 忙碌时整条处理链跳帧，不显示未经第二阶段处理的新帧。取消编译、尺寸不支持、任一上下文丢失及关闭都释放两阶段并回原图。诊断的总 GPU 耗时在串联时留空，处理链只报告已有的第一阶段 GPU 测量，不假造总耗时。

scripts/test-anime4k.cjs 已运行真实两引擎：64×36→128×72→256×144，透明误差约 1.01/255，输出非空；验证两阶段次序、位置不变、取消编译、降档提示、保留偏好、销毁回收。小图测试证明正确性，不代表 4K 实际帧率，也不声称本机测试显卡是用户的 9070XT。
